# クレジットカード決済 テスト用業務要件

- 対象: `igisu/Bento`（想定ブランチ: `main`）
- 対象: .NET Framework / Windows Forms / SQL Server
- 目的: Codexによる現行実装の適合性検証。**本書は実装修正指示ではない**
- 作成日: 2026-11-18
- 根拠: 利用者による第1〜5回および追加確認の回答
- 状態: `確定` / `未定` / `統合`。コードとの一致は未検証

## 運用上の注意
1. 業務要件と現行実装の観察・疑義を混同しない。
2. `未定`をCodexが独自に確定しない。テスト結果は`BLOCKED_SPEC`とする。
3. 外部決済APIへの実通信および本番DBへの書き込みを禁止する。
4. 結果不明状態は、明確な失敗と区別する。管理者復旧前の再実行は禁止。
5. 受け入れ条件の期待値は人間が承認するまで変更しない。

## 重要な解釈
- REQ-CC-004の「状態確定まで禁止」より、REQ-CC-010の「管理者復旧まで禁止」を厳格な条件として適用する。
- REQ-CC-027は結果不明の請求を再決済可能にする意味ではない。
- REQ-CC-032は入金明細の重複を正当化しない。締め直し可否とデータ整合性は別の検証項目。
- REQ-CC-020は未定であり、現行コードに自動復旧がないことだけで「仕様違反」とは判定しない。ただし既存の再決済禁止要件に反する経路は検証する。
- REQ-CC-033の具体復旧方式は未定。ただしREQ-CC-021で規定する結果不明時の禁止動作を無効化しない。
