# Codex 作業指示 — クレジットカード決済テスト

## 目的・対象
- 本リポジトリの .NET Framework / Windows Forms / SQL Server を用いるクレジットカード決済機能について、承認済み業務要件への適合性を検証する。
- 対象フォーム: Form500, Form501, Form502, Form503, Form506, Form508, Form509, Form510, Form511, Form512, Form512D, Form513, Form513B, Form513D, Form514, Form515, Form700, Form700D, Form818, Form819。関連クラス・DB処理も対象。
- `docs/requirements.md`、`docs/acceptance-criteria.md`、`docs/test-cases.md`を先に読む。要件IDとテストIDを維持する。

## 最重要の安全制約
1. 実際の決済・取消・カード削除などの外部APIを**呼び出さない**。外部APIはモック/スタブを使う。テストで本番資格情報を使用しない。
2. 本番DB・共有DBへの接続・更新を行わない。DBが必要な場合は隔離テストDBを使用し、接続先を実行前に確認する。安全性が確認できなければ実行せず `BLOCKED_ENV` とする。
3. 既存の業務ロジックをテスト合格のために修正しない。仕様書・受け入れ条件・期待結果を勝手に書き換えない。修正提案とテスト実装は区別する。
4. シークレット、APIキー、カード情報、個人情報をログ・成果物・コミットに含めない。
5. 既存のテストや警告を削除・無効化して合格に見せない。

## 進め方
1. 対象フォームと関連クラスを調査し、要件ID → 受け入れ条件 → テストケースID → ファイル/メソッドの対応を補完する。
2. .NET Framework のバージョン、テスト基盤、SQL Server依存、外部API依存、Windows専用の実行条件を確認する。
3. 正常系・異常系・境界値・同時実行・通信断・DB保存失敗・取消・締め直しをテスト設計する。
4. 実行可能なものだけを安全な環境で実装・実行する。外部サービス呼出しがモック化できない場合は実行しない。
5. テスト結果を証跡付きで報告する。ソースの静的確認のみの場合は `REVIEW_ONLY` とし、実行済みの `PASS` と区別する。

## 重要な業務上の禁止事項・確認点
- 決済結果不明（タイムアウト、通信断等）は明確な失敗と区別し、管理者確認・復旧まで再決済禁止（REQ-CC-010）。
- 同一請求への同時決済は先行処理のみ許可（REQ-CC-011）。
- 取消結果不明時は管理者復旧まで再取消・再決済・請求変更禁止（REQ-CC-021）。
- 一括決済で一件が結果不明でも、その請求を保護し後続を続行（REQ-CC-027）。
- 強制終了後の具体的な自動検知・復旧方式（REQ-CC-020）と、取消API成功後DB更新失敗の具体的復旧方式（REQ-CC-033）は**仕様未定**。推測で確定しない。
- 取消後の入金明細が残存していても締め直しを許可する（REQ-CC-032）。残存による不整合は別途リスク報告し、締め直し許可そのものを不具合扱いしない。

## 報告書式
- 各テスト: テストID、要件ID、対象メソッド、入力/障害注入、期待結果、実測結果、証跡、判定。
- 判定: `PASS` / `FAIL` / `BLOCKED_ENV` / `BLOCKED_SPEC` / `REVIEW_ONLY` / `NOT_RUN`。
- 不具合候補と再現確認済み不具合を区別する。実行していないテストを合格扱いしない。
- 追加パッケージ、テスト用ファイル、DB構築が必要なら内容と理由を報告する。
